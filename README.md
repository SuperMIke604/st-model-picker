# ST Tools（酒馆增强套件）

一个 SillyTavern 扩展，打包三个功能，各自独立开关：

1. **模型选择器**：把模型下拉框换成「点击弹窗 + 搜索框 + 分组列表」的单选选择器，PC 与移动端通用
2. **聊天文件增强**：「管理聊天文件」弹窗秒开（骨架屏过渡）+ 一键复制聊天文件
3. **聊天视图与目录**：超长聊天一页一页读（分页 / 虚拟化 / 窗口三种模式可选）+ 魔法棒「聊天目录」跳转

全程零核心代码改动。

## 一、模型选择器

- **可搜索**：按模型名或分组实时过滤（大小写不敏感，同时匹配文本与 value）
- **弹窗式**：基于 SillyTavern 原生 Popup（`<dialog>`），与整体 UI 一致
- **PC / 移动端通用**：不依赖 select2，移动端同样可用
- **键盘友好**：`↑`/`↓` 移动 → `Enter` 选中 → `Esc` 关闭
- **无侵入**：原生 `<select>` 只隐藏不删除，核心的设置读写、`change` 事件、斜杠命令全部照常工作；连接 API 后动态拉取的模型也能搜到（列表每次打开时实时读取）

## 二、聊天文件增强

- **秒开**：核心逻辑是「先请求 `/api/chats/search` 并渲染完所有条目，再显示弹窗」，而该接口在服务端会逐个串行读取每个聊天 jsonl 文件，文件多时要干等。本扩展改为：点击后**立即弹窗 + 骨架屏**，再异步填充列表
- **复制**：每个聊天文件条目的操作区多一个复制按钮
  - 角色聊天：`/api/chats/get` → `/api/chats/save`，新文件名自动去重（`xxx (copy)`、`xxx (copy 2)`…）
  - 群聊：`/api/chats/group/get` → `/api/chats/group/save`，并把新聊天 id 写回群元数据的 `chats` 数组
  - 复制完成后自动刷新列表
- **零核心改动**：只调用官方 API

## 三、聊天视图与目录

思路和小说阅读器一致：**绝不把全部消息放进 DOM**。提供三种渲染模式，可在设置里随时切换。

### 模式一：分页阅读（默认，推荐）

起点中文网网页版那种读法：按固定楼数（默认 20 楼）把整段聊天切成若干页，**一次只渲染当前页**，底部常驻翻页条。

- **翻页条**：`上一页 · 第 X / Y 页 · #起–#止 · 共 N 楼 · 下一页 · 最新`，首页/末页时对应按钮置灰
- **页内正常滚动**：一页就是一段完整的聊天，上下滚随便看；阅读体验不受影响
- **跳转永远精确**：因为是整页替换，不存在「估算高度」这个环节，点目录章节必定落在目标楼
- **规模恒定**：页数再多，DOM 里也只有一页（默认 20 条），800 楼和 8000 楼的打开速度、删除速度完全一样
- **末页即最新**：翻到最后一页时停在底部，跟点「最新」的落点一致

### 模式二：虚拟化

- **滚动条覆盖全部楼层**：用上下两个占位元素把「未挂载楼层」的高度撑出来。不管聊天有 800 楼还是 8000 楼，滚动条都能直接拖到任意位置
- **只挂载视口附近**：DOM 里始终是 5~10 条，滚动时动态装卸
- **跳转一次到位**：点目录章节直接按高度索引算出偏移量，不需要逐段加载

实测（802 楼聊天）：

| 模式 | DOM 消息数 | 浏览方式 |
|---|---|---|
| 关闭本功能 | 20 | 核心自己的截断，滚动条只有 20 楼 |
| **分页阅读** | **4**（末页）／ 20（整页） | 一页一页翻，底部翻页条 |
| 虚拟化 | 5~10 | 滚动条覆盖全部 802 楼，滚动即装卸 |
| 窗口 | 10 | 下滑续载、向上按段加载 |

### 模式三：窗口

打开聊天时只渲染最新 `每次加载楼层数` 条（默认 10），滚动条长度等于当前窗口，需要按段加载。

### 三种模式共有的能力

- **聊天目录**：分页模式点**翻页条最左边的「目录」按钮**；虚拟化 / 窗口模式在魔法棒菜单 →「聊天目录」。列出全部**用户发言楼层**作为章节
  - 章节名 = 楼层号 + 内容预览，形如 `#101 + #102`（用户楼 + 其回复楼；若下一楼仍是用户发言则只有 `#101`）
  - 楼层编号与 SillyTavern 一致（从 0 开始）
  - 支持关键词搜索（同时匹配楼层号与内容预览），当前所在章节高亮
  - 弹窗底部「跳到最新」一键回到最新窗口
- **跳转**：点击章节后渲染该章所在的区间，并把该楼滚到顶部
  - 分页：算出目标楼所在的页码，整页渲染后把它对齐到页顶（实测 802 楼跳转 51ms）
  - 虚拟化：按高度索引直接算出偏移量
  - 窗口：重新渲染一段窗口
- **连续浏览**：
  - 分页：页内自由滚动，翻页条换页；末页就是最新
  - 虚拟化：滚动即装卸，无需任何按钮，一路滑到底就是最新
  - 窗口：下滑到底自动追加后续 N 楼；顶部「加载更早的消息」向前补 N 楼并保持滚动位置不跳；DOM 超过「DOM 最多保留消息数」就从另一端裁掉
- **新消息自动回到底部**：停在旧楼层时收到新回复，自动跳回最新（可关）

- **删除楼层**：核心删完会按 DOM 顺序重排 `mesid`，本功能跟着做一次校正
  - 分页：核对 DOM 里的区间还是不是当前页（核心会顺手重排最后 N 条），对不上就整页重渲染，保证画面与页码一致；吻合时只刷新页码，删除本身不拖泥带水（实测 147ms）
  - 窗口 / 虚拟化：把窗口尾部补齐（异步，不阻塞删除操作），避免后续编辑 / 滑动 / 续载错位

### 为什么不用核心的 `power_user.chat_truncation`

核心 `printMessages()` 本身就只渲染最后 `power_user.chat_truncation` 条。但那是**共享字段**，常被别的优化类扩展占用（例如 cocktail 的「首屏渲染条数」），直接改会互相打架。因此本功能不碰它，改为在核心渲染完成后自行裁剪窗口。

同理，顶部加载按钮用的是自有 id（`#stcv_show_more`）而非核心的 `#show_more_messages`——后者被多个扩展监听（含「滚到顶部就自动加载更早」），而跳转后必然停在顶部，会被立刻触发、把刚裁掉的旧楼层又灌回来。

### 虚拟化的三个实现要点

1. **不自己造 `.mes` 的 DOM**。消息气泡仍由核心的 `updateMessageElement()` 产出，所以所有依赖 `.mes` 结构的扩展（data_table、cocktail、JS-Slash-Runner 等）照常工作，我们只决定「哪几条在 DOM 里」和「上下补多高」。
2. **用占位元素而不是 padding**。`#chat` 是 `display:flex` 的滚动容器，给它加 padding 会把容器自身撑大（实测 `clientHeight` 从 399 变成十万级），视口高度彻底失真。占位元素是 flex item，不改变容器高度。
3. **高度不必一开始就知道**。没量过的楼层先估算，进入视口后实测回填并补偿 `scrollTop`，避免画面跳动。实测值按消息对象存进 `WeakMap`，所以删除楼层导致索引位移后缓存依然命中；有实测样本后改用「每字符平均高度」估算，滚动条漂移更小。

挂载消息时会补发 `*_MESSAGE_RENDERED` 事件，让扩展有机会装饰这些后加载出来的消息。

## 安装

方式一（推荐）：SillyTavern 扩展面板 →「安装扩展」→ 填入本仓库地址。

方式二（手动）：把本目录整个复制到：

```
SillyTavern/public/scripts/extensions/third-party/st-model-picker/
```

刷新页面即可，无需重启。

## 使用

- **模型选择器**：AI 设置面板 → 点击任意模型下拉（右侧带放大镜图标）→ 搜索并选择
- **聊天文件增强**：魔法棒菜单 →「管理聊天文件」→ 弹窗立即出现；条目操作区点击复制图标即可生成副本
- **聊天目录**：分页模式点底部翻页条的「目录」按钮（虚拟化 / 窗口模式在魔法棒菜单）→ 搜索 / 点击章节跳转

## 文件结构

```
index.js         入口：加载设置面板 + 初始化三个功能
settings.js      设置读写（含旧版扁平结构迁移）
utils.js         翻译 / 上下文 / JSON POST 公共工具
model-picker.js  功能一：模型选择器
chat-files.js    功能二：聊天文件增强
chat-toc.js      功能三：目录弹窗 + 窗口模式渲染 + 三种模式的调度入口
chat-pager.js    功能三：分页阅读（切页 + 底部翻页条）
chat-virtual.js  功能三：虚拟化渲染（高度索引 + 占位 + 视口挂载）
style.css        三个功能的样式（.stmp_* / .stcfp_* / .stcv_* / .stvv_*）
settings.html    扩展面板 UI
```

## 已知边界

- 斜杠命令（如打开管理界面）走核心原生路径，不经过本扩展的秒开拦截
- 群聊复制时若群元数据写入失败，副本文件已生成但不会出现在群聊列表中（文件仍在磁盘，可手动恢复）
- 服务端串行扫描的性能瓶颈仍在（本扩展解决的是「感知等待」）；彻底提速可将 `src/endpoints/chats.js` 中 `/search` 的串行循环改为有并发上限的并行读取
- 聊天目录只把**用户发言楼层**作为章节（按需求设计），连续多轮助手回复不会被单独列出
- 改动的是渲染层，导出的聊天文件、正则、世界书、统计等读取 `chat` 数组的功能均不受影响
- 分页模式下滚动条只覆盖当前这一页，要跳到远处请用「聊天目录」或直接点翻页条——这正是分页的取舍：用「不能一拖到底」换「跳转永远精确、DOM 规模恒定」。想保留长滚动条就切到虚拟化模式
- 虚拟化模式下，未挂载的楼层高度先用估算值，进入视口后才替换成实测值，因此首次拖动滚动条时可能有轻微的位置校正（消息高度越均匀越不明显）
- 少数扩展按「DOM 里第 N 个 `.mes`」定位消息，虚拟化下 DOM 只有几条，这类扩展在处理后加载的消息时可能报错（它们通常自己会捕获，不影响聊天本身）
