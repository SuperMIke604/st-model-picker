# ST Tools（酒馆增强套件）

一个 SillyTavern 扩展，打包三个功能，各自独立开关：

1. **模型选择器**：把所有模型下拉框（含自带搜索的 select2 下拉）换成「点击弹窗 + 搜索框 + 分组列表」的单选选择器，PC 与移动端通用
2. **聊天文件增强**：「管理聊天文件」弹窗秒开（骨架屏过渡）+ 一键复制聊天文件
3. **聊天视图与目录**：超长聊天一页一页读（分页阅读）+ 底部翻页条上的「聊天目录」跳转

全程零核心代码改动。

## 一、模型选择器

- **可搜索**：按模型名或分组实时过滤（大小写不敏感，同时匹配文本与 value）
- **弹窗式**：基于 SillyTavern 原生 Popup（`<dialog>`），与整体 UI 一致
- **PC / 移动端通用**：不依赖 select2，移动端同样可用
- **键盘友好**：`↑`/`↓` 移动 → `Enter` 选中 → `Esc` 关闭
- **无侵入**：原生 `<select>` 只隐藏不删除，核心的设置读写、`change` 事件、斜杠命令全部照常工作；连接 API 后动态拉取的模型也能搜到（列表每次打开时实时读取）

## 二、聊天文件增强

- **秒开**：核心逻辑是「先请求 `/api/chats/search` 并渲染完所有条目，再显示弹窗」，而该接口在服务端会逐个串行读取每个聊天 jsonl 文件，文件多时要干等。本扩展改为：点击后**立即弹窗 + 骨架屏**，再异步填充列表
- **复制**：每个聊天文件条目的操作区多一个复制按钮
  - 角色聊天：`/api/chats/get` → `/api/chats/save`，新文件名自动去重（`xxx (copy)`、`xxx (copy 2)`…）
  - 群聊：`/api/chats/group/get` → `/api/chats/group/save`，并把新聊天 id 写回群元数据的 `chats` 数组
  - 复制完成后自动刷新列表
- **零核心改动**：只调用官方 API

## 三、聊天视图与目录

思路和小说阅读器一致：**绝不把全部消息放进 DOM**。只有一种形态 —— 分页阅读。

起点中文网网页版那种读法：按固定楼数（默认 20 楼）把整段聊天切成若干页，**一次只渲染当前页**，底部常驻翻页条。

- **翻页条**：`目录 · 上一页 · 第 X / Y 页 · #起–#止 · 共 N 楼 · 下一页 · 最新`，首页/末页时对应按钮置灰
- **页内正常滚动**：一页就是一段完整的聊天，上下滚随便看；阅读体验不受影响
- **跳转永远精确**：因为是整页替换，不存在「估算高度」这个环节，点目录章节必定落在目标楼
- **规模恒定**：页数再多，DOM 里也只有一页（默认 20 条），800 楼和 8000 楼的打开速度、删除速度完全一样
- **末页即最新**：翻到最后一页时停在底部，跟点「最新」的落点一致

实测（1440×900，804 楼聊天）：

| 模式 | 打开耗时 | DOM 消息数 |
|---|---|---|
| 关闭本功能 | 298ms | 20（核心自己的截断） |
| **分页阅读** | **429ms** | **20**（一整页） |

跳转 #200 实测 **51ms**，精确落在 `第 11 / 41 页 · #200–#219`。

### 聊天目录

翻页条最左边的「目录」按钮打开弹窗，列出全部**用户发言楼层**作为章节：

- 章节名 = 楼层号 + 内容预览，形如 `#101 + #102`（用户楼 + 其回复楼；若下一楼仍是用户发言则只有 `#101`）
- 楼层编号与 SillyTavern 一致（从 0 开始）
- 支持关键词搜索（同时匹配楼层号与内容预览），当前所在章节高亮
- 弹窗底部「跳到最新」一键回到最后一页
- 点击章节 → 算出目标楼所在的页码 → 整页渲染后把它对齐到页顶

### 其他细节

- **新消息自动回到底部**：停在旧页时收到新回复，自动跳回最后一页（可关）
- **删除楼层**：核心删完会按 DOM 顺序重排 `mesid`，还会顺手重排一次 DOM（渲染最后 N 条）。因此这里核对 DOM 区间是否仍是当前页，对不上就整页重渲染，保证画面与页码一致；吻合时只刷新页码，删除本身不拖泥带水（实测 147ms）
- **切换聊天**：打开 / 切换聊天后统一停在最后一页底部
- **不碰核心的 `power_user.chat_truncation`**：它被别的优化扩展（例如 cocktail 的「首屏渲染条数」）共享占用，改了会互相打架。本功能改为在核心渲染完成后自行换页
- **不自己造 `.mes` 的 DOM**：消息气泡仍由核心的 `redisplayChat()` 产出，所以所有依赖 `.mes` 结构的扩展（data_table、cocktail、JS-Slash-Runner 等）照常工作，本功能只决定「哪一页在 DOM 里」

## 安装

方式一（推荐）：SillyTavern 扩展面板 →「安装扩展」→ 填入本仓库地址。

方式二（手动）：把本目录整个复制到：

```
SillyTavern/public/scripts/extensions/third-party/st-model-picker/
```

刷新页面即可，无需重启。

## 使用

- **模型选择器**：AI 设置面板 → 点击任意模型下拉（右侧带放大镜图标）→ 搜索并选择
- **聊天文件增强**：魔法棒菜单 →「管理聊天文件」→ 弹窗立即出现；条目操作区点击复制图标即可生成副本
- **聊天目录**：底部翻页条最左边的「目录」按钮 → 搜索 / 点击章节跳转

## 文件结构

```
index.js         入口：加载设置面板 + 初始化三个功能
settings.js      设置读写（含旧版扁平结构迁移）
utils.js         翻译 / 上下文 / JSON POST 公共工具
model-picker.js  功能一：模型选择器
chat-files.js    功能二：聊天文件增强
chat-toc.js      功能三：目录弹窗 + 功能开关收口
chat-pager.js    功能三：分页阅读（切页 + 底部翻页条）
style.css        三个功能的样式（.stmp_* / .stcfp_* / .stcv_*）
settings.html    扩展面板 UI
```

## 已知边界

- 斜杠命令（如打开管理界面）走核心原生路径，不经过本扩展的秒开拦截
- 群聊复制时若群元数据写入失败，副本文件已生成但不会出现在群聊列表中（文件仍在磁盘，可手动恢复）
- 服务端串行扫描的性能瓶颈仍在（本扩展解决的是「感知等待」）；彻底提速可将 `src/endpoints/chats.js` 中 `/search` 的串行循环改为有并发上限的并行读取
- 聊天目录只把**用户发言楼层**作为章节（按需求设计），连续多轮助手回复不会被单独列出
- 改动的是渲染层，导出的聊天文件、正则、世界书、统计等读取 `chat` 数组的功能均不受影响
- 分页读法下滚动条只覆盖当前这一页，要跳到远处请用「聊天目录」或直接点翻页条——这正是分页的取舍：用「不能一拖到底」换「跳转永远精确、DOM 规模恒定」
- 模型选择器会把原生 select2 下拉一并拆掉换成弹窗选择器（OpenRouter / Chutes / NanoGPT 这类自带搜索的也一样）。若有某个来源的下拉你不希望被接管，在设置面板的「接管的模型下拉」里取消勾选它
